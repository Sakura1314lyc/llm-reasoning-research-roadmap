# OpenClaw、Hermes、Codex、Claude Code 与 Harness

这些工具的安装方式和模型支持改得很快，所以这里只记比较稳定的观察维度，不抄一套很快就会过期的安装命令。实际安装和许可证以各自的当前官方文档为准。

## 比较工具时看什么

| 维度 | 检查内容 |
| --- | --- |
| Model | 使用云端 API、本地模型还是可替换 Provider |
| Agent loop | 如何规划、调用工具、处理错误和终止 |
| Tools | Shell、文件、浏览器、Git、代码执行的权限边界 |
| Context | 仓库规则、会话历史、检索和压缩策略 |
| Extension | Skill、Plugin、MCP、Hook 或自定义 Agent |
| Harness | 工作区隔离、审批、日志、测试、回滚和评审 |

## Harness 不只是 Prompt

Harness 是承载 Agent 的整套工程系统，里面包括模型路由、工具协议、权限审批、沙箱、上下文组装、状态持久化、日志、测试和恢复。开始调轨迹以前，先确认 Harness 能稳定复现同一个任务。不然效果变化到底来自模型、Prompt、Skill 还是工具环境，很难说清。

LangChain 等框架可以编排模型、工具和状态。课程仍然先手写最小循环，等数据流看清楚了，再和框架组件一一对应。这样出了错，能分辨问题在模型决策、参数校验、工具执行还是状态更新，不会把 Agent 能力简单等同于某个框架 API。

## 实际跑一遍时

1. 在隔离的测试仓库运行，不直接给生产凭据。
2. 检查项目级规则文件和忽略文件是否生效。
3. 分别测试读取、修改、测试、Git 操作和失败恢复。
4. 配置一个只读 MCP Server，再尝试有副作用的工具。
5. 把重复工作流写成 Skill，明确触发、输入、步骤、验证和安全边界。
6. 用固定任务集比较成功率、平均步骤、无效调用和耗时。

任务二只要求完成基础配置时，可把版本、Provider、MCP/Skill 清单和一次成功轨迹记录在本地，不需要把账号、Token 或个人配置提交到仓库。
